Severity: **P1** blocks a milestone or violates a product rule · **P2** should fix before freeze · **P3** tracked, not blocking.

| D-14 | 4 Oct, identity lane merge | P1 | Supersedes D-13's fix, which was itself wrong in a way D-13's own verification could not have caught: `Starlette(routes=[Mount(root_path, app=app)])` routes HTTP correctly (`Mount` dispatches straight to the sub-app, so `request.app` still resolves to the inner app) but the *outer* `Starlette` has no `lifespan` of its own, and Starlette's `Router` never cascades a `lifespan` ASGI scope down into a mounted sub-app — so the inner app's own `lifespan` (every service's Mongo connection, signing-key load, readiness-check registration) silently never ran. The failure was deceptive by construction: `/healthz` still returned 200 (no lifespan-set state needed), and `/readyz` returned 200 *vacuously* (no checks had been registered to fail), which is exactly why D-13's own Docker verification — which checked `/healthz`/`HEALTHCHECK`-reports-`healthy` — did not catch it. Surfaced when the identity-service lane's `GET /.well-known/jwks.json` 500'd with `AttributeError: 'State' object has no attribute 'signing_key'` (set only in `lifespan`), reproduced live with a real Mongo container when I went to independently verify that lane's own Dockerfile. | `src/packages/common/fcrm_common/asgi.py` (`mount_at_root_path`'s `Starlette`+`Mount` implementation). | **Resolved**: rewrote `mount_at_root_path` as a thin functional ASGI wrapper (not a second Starlette app) that rewrites `path`/`root_path` for `http`/`websocket` scopes and forwards every other scope type — critically `lifespan` — straight to the wrapped app untouched, so the wrapped app's own ASGI `__call__` handles its own lifespan exactly as it would unmounted. Added a regression test (`test_mount_at_root_path_still_runs_the_wrapped_app_s_lifespan`) asserting lifespan-set state is actually visible through a mounted app, which would have caught this the first time. Re-verified live end to end for both services: scoring's `/readyz` against a real Mongo container now shows real `mongo`/`recompute` checks (not an empty list) and the 80-case seed self-test actually running; identity's JWKS endpoint now returns real keys instead of 500ing. Also added `src/services/identity/Dockerfile` (the one Dockerfile the prior lane had to skip, since the service didn't exist yet). |
