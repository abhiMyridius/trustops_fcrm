# ai/CLAUDE.md

Rules for Claude Code and its subagents working under `ai/`. Read `ai/README.md` for what each folder is. Design reference: `docs/architecture/design/B-ai-layer.md` §1.9.

## Never

- Never edit a committed prompt file. Add `<id>.v<N+1>.md` with a changelog entry, and leave `v<N>` as it is.
- Never write a model id anywhere except `ai/models/tiers.yaml`, including examples, comments and docs. Name the tier instead. The lock test fails on any other occurrence.
- Never give an agent a tool that writes, and never give any agent a scoring tool (ADR-07). Scores come only from `fcrm_scoring`, which H1 calls.
- Never put a case variable in a system prompt. System prompts are the cached prefix: they may use `versions`, `thresholds`, `skill()`, `schema()`, `config()` and the load-time `mode` constant only. No ids, dates or case text.
- Never define an output shape here. Output models live in `src/backend/packages/contracts`, and agent specs point at them by dotted path. A prompt names the contract's item types and only the fields that exist on them (`tests/unit/packages/prompts_loader/test_system_prompts_match_contracts.py` keeps the two aligned). It does not paste `{{ schema(...) }}` while the output tool already sends the JSON schema: the copy cost 0.5 to 1.5k tokens a request in the first live run and told the model nothing the tool did not.
- Never rely on a model to guess a citation handle. Say which `source_ref` each kind of claim carries (the `cite_verbatim` skill lists them) and make the pack print the ids the model must copy (the list handle, the gap id, the document id).
- Never raise a budget, a cap or a threshold without a decision-log row.
- Never hand-write files in `ai/schemas/` (generated by `make schemas`) or `ai/registry.lock/` (generated by `make locks`).

## Always

- Run `make evals AGENT=<name>` before moving a `current:` pointer in `prompts/MANIFEST.yaml`, and record the run id in the new file's changelog.
- After any change under `ai/`, run `make locks` (until it exists: `python3 ai/_tools/compute_locks.py`) and `python3 ai/_tools/validate_ai.py`.
- To add a tool, change four things in one commit: the tool YAML, the agent's `tools` or `pack_tools`, the matching row in `policies/tool_permits.json` (and its `tools` registry list), and one contract test.
- Give every claim-bearing output field provenance: a `Claim` with `source_ref`, a verbatim `quote` and `confidence`. Give every absence a `Searched` block.
- Keep `agents/*.agent.yaml` `tools` and `pack_tools` identical to `policies/tool_permits.json`. `validate_ai.py` and `opa test ai/policies` both check this.
- Write prompts in plain instructional language: the task, the hard rule, the limits, the output. No padding, no "As an AI", no flattery.
- When the committed contract cannot carry what a prompt needs, do not work around it silently. Add the field under `contract_changes_required` or mark the part `pending_contract` in the agent spec, and tell the lead.

## Where things are decided

| Question | Source |
|---|---|
| Which model a tier uses | `models/tiers.yaml`, ADR-04 |
| Which tools an agent may call | design B §2.x for the agent, mirrored in `policies/tool_permits.json` |
| Retry and fallback order | ADR-14: attempt 1 is `FallbackModel(primary, fallbacks)`; attempt 2 is the first fallback alone with the validation error |
| Guard order and behaviour | `guards/guards.yaml`, design B §4 |
| What the PO may never read | `guards/restricted_terms.txt`, rule 3, D-62 |
