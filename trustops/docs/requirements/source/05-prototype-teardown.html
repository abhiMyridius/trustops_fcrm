Case lifecycle

The status values in the code, and the gates that move a case between them.

stateDiagram-v2
  [*] --> Draft: PO opens case, ID issued
  Draft --> Draft: validation fails, intake reopens
  Draft --> Submitted: gate passes, 80% filled plus every always-required field
  Submitted --> UnderAssessment: auto-triage assigns analyst
  UnderAssessment --> UnderAssessment: clarification round, new submission version
  UnderAssessment --> Closed: band 1 or 2, analyst signs off
  UnderAssessment --> CommitteeReview: band 3 or 4, pack approved
  CommitteeReview --> Approved: majority of 3 votes
  CommitteeReview --> Rejected: majority of 3 votes
  Approved --> [*]
  Rejected --> [*]
  Closed --> [*]
  state "Under Assessment" as UnderAssessment
  state "Committee Review" as CommitteeReview

The brief also lists "deferred" and "approved with conditions" as outcomes. The prototype's status list does not have them yet.

Stack and structure

Front end: React 19, TypeScript, Vite 8, Tailwind 4, React Router 7, Recharts, Framer Motion.

Backend: none. No database, no auth, no network calls. Service functions fake a delay and read an in-memory store.

Good seam: screens only call the two service files. Swap function bodies for HTTP calls and the UI stays as is.

Missing source: the code cites a spec by section (§1 to §10, 300+ references). That spec is not in the repo.

Things to raise with the BA

  • PO has an AI Configuration page that sets model and effort for intake agents. This clashes with the rule that the business owner cannot configure their own gate. Suggest moving it to analyst Config.
  • PO also has Integrations (connect SharePoint and similar to import documents). Fine to keep, but it is extra scope. Decide if it is in or out for 9 Oct.
  • Outcomes missing: the brief names four outcomes (approved, rejected, deferred, approved with conditions). The code has approved and rejected only.
  • The "Evoq" logo sits in the sidebar. Confirm it is allowed in the submission.
  • Ask for the numbered spec that the code cites. It is the core of the requirements folder.
  • Correction to my earlier note: the band gaps (10.0 to 10.1) are safe. The composite is rounded to one decimal before the band lookup. Still worth a unit test.
