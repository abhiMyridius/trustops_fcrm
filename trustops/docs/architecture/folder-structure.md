# Folder structure (as built)

> **This tree is the repository as it was on 6 October 2026, read from the filesystem.** The design-time tree this file used to hold put one Dockerfile in every service and worker and the web app under `src/web`. ADR-26 (5 Oct) split `src/` into `src/backend/` and `src/frontend/` and replaced 24 containers with eight; ADR-25 moved the project into `trustops/` inside the `trustops_fcrm` repository next to `Documents/` (the approved spec set) and `FCRM_v2/` (the BA's prototype, reference only). Where the build departs from the plan, `BUILD-PLAN.md`, section "Status as built", says why.

Python units follow one template: `pyproject.toml` and an import package `fcrm_<name>/` with source only. There is **one** `Dockerfile` for every Python process (`src/backend/Dockerfile`) and one for the web (`src/frontend/Dockerfile`). Tests live under `tests/unit` and `tests/integration` at the same relative path as the source (ADR-21). Tool configuration (`ruff.toml`, `mypy.ini`, `pytest.ini`) sits at the project root, never inside `src/`. Clones of AEO code carry an `UPSTREAM.md` listing the source commit and every change.

Counts: 6 services and 4 workers (10 units) in 2 processes · 8 packages · 1 web app · 9 agents · 13 tools · 5 skills · 7 guards · 8 rules · 8 containers by default (12 with `obs`, 9 with `cache`) · 110 API paths · 21 walkthrough scenes · 13 black-box test files for 12 scenarios under `tests/integration/blackbox`, plus six named skips.

Not built, though earlier versions of this tree listed them: `tests/e2e`, `tests/resilience`, `tests/perf`, `ops/scripts/{seed_verify,demo,backup,restore,claude_usage}`, `ops/reports/nightly`, `ops/token-analysis`, `docs/architecture/events/` and per-service OpenAPI files (the export is one merged file), `ai/schemas/` content, a `packages/skills` unit (skills are files under `ai/skills` loaded by `fcrm_prompts`), and per-package `CLAUDE.md` files (only the root, `ai/` and `src/frontend/` have one). See `docs/governance/known-gaps.md`.
